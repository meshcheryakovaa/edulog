# История изменений EduLOG

Что и когда появилось в приложении и как этим пользоваться. Записи идут
по порядку, от первых к последним. В скобках указан номер pull request
на GitHub.

Если в записи сказано «выполнить `schema.sql` ещё раз», это значит:
после обновления сайта откройте Supabase → SQL Editor и выполните файл
[`supabase/schema.sql`](supabase/schema.sql) целиком. Скрипт можно запускать
повторно, существующие данные он не трогает.

С 14 ноября 2026 (#19) это делается автоматически через GitHub Actions, если
задан секрет `SUPABASE_DB_URL` (см. README, раздел «Автоматическое обновление
схемы»). Вручную запускать не нужно.

## 6 ноября 2026

### Исходный код и выпуск одним HTML-файлом (#1)

**Что появилось.** Приложение «План и расписание» разобрано на исходники
(`src/`) и собирается обратно в один файл `edulog.html`.

**Как это работает.**
- Команда `node scripts/build.mjs` встраивает стили, скрипт и примеры данных
  в один файл `dist/edulog.html`. Никаких зависимостей ставить не нужно,
  достаточно Node 18+.
- При каждом push в `main` GitHub собирает файл автоматически.
- Чтобы выпустить релиз, поставьте тег: `git tag v1.0.0 && git push origin v1.0.0`.
  Готовый `edulog.html` появится на странице
  [релизов](https://github.com/meshcheryakovaa/edulog/releases).
- Файл открывается в любом браузере без сервера. Отметки зачётов сохраняются
  в браузере, PDF скачивается обычной загрузкой.

### Сайт на GitHub Pages (#2)

**Что появилось.** Приложение доступно по адресу
**https://meshcheryakovaa.github.io/edulog/**.

**Как это работает.** После каждого push в `main` собранный файл
публикуется на сайт автоматически, ничего вручную делать не нужно.
Один раз потребовалось включить Pages: Settings → Pages → Source: GitHub Actions.

### Многопользовательский режим и раздел администратора (#3, #4, #5)

**Что появилось.** Вход по email и паролю, роли пользователей и общие
данные для всех на базе Supabase.

**Как это работает.**
- **Вход и регистрация.** Пользователь регистрируется по email и паролю,
  подтверждает адрес по ссылке из письма. Есть восстановление пароля.
- **Роли.** Новый пользователь получает роль «Ожидает» и данных не видит,
  пока администратор его не одобрит. Дальше роль может быть «Просмотр»,
  «Редактор», «Администратор» или «Заблокирован». Первый
  зарегистрированный пользователь сразу становится администратором.
- **Общие данные.** Редактор нажимает «Открыть файлы…», проверяет, что план
  и расписание разобрались, и нажимает «Опубликовать». Эту версию видят все.
  «Вернуть опубликованное» отменяет файлы, открытые локально.
- **Отметки зачётов общие.** У роли «Просмотр» флажки только для чтения.
- **Раздел «Администрирование».** Заявки на доступ (одобрить или отклонить),
  смена ролей, список опубликованных файлов (кто и когда, снять
  с публикации), журнал действий.
- **Права проверяются на сервере**, поэтому нельзя повысить себе роль,
  снять последнего администратора или читать данные без одобрения.
- Если Supabase не настроен, приложение работает локально, как раньше,
  со встроенными примерами.
- В #4 к сайту подключён проект Supabase, в #5 исправлена ошибка
  «Ошибка сервера (405)» при входе: теперь в настройках можно указать
  просто идентификатор проекта, адрес достраивается сам.

### Расписание по неделям и журнал изменений (#6)

**Что появилось.** Файл расписания больше не заменяет всю базу, а обновляет
только свои недели. Все изменения записываются в журнал.

**Как это работает.**
- В базе хранится расписание по неделям. Загруженный файл содержит одну или
  несколько недель, и в базе заменяются только они (неделя узнаётся по дате
  понедельника, а если дат нет, то по номеру). Остальные недели остаются.
- **Вкладка «Изменения»** показывает журнал загрузок: какие недели новые,
  обновлены, без изменений или удалены. По обновлённым неделям видно,
  какие занятия добавлены, отменены или изменены («было → стало», отличия
  подсвечены). Можно оставить только выбранную группу, преподавателя или
  аудиторию. Там же список недель в базе, ошибочную неделю можно удалить.
- **В расписании** занятия помечены «Новое» или «Изменено» (во всплывающей
  подсказке видно, как было), отменённые показаны пунктиром. Под сеткой
  есть панель «Изменения этой недели».
- **В недельном плане** недели с изменениями отмечены точкой в шапке
  таблицы, а внизу список изменений расписания.
- В списке слева пометка «изм.» стоит у тех, кого коснулась загрузка.
- После обновления нужно выполнить `schema.sql` ещё раз.

### Подгруппы в ячейке пары (#7)

**Что появилось.** Занятия подгрупп показываются в своей половине ячейки.

**Как это работает.** Занятие всей группы занимает ячейку целиком,
1 подгруппа стоит слева, 2 подгруппа справа. Если занята только одна
подгруппа, вторая половина показана пустой пунктирной рамкой «1 п/г —»
или «2 п/г —». Так же устроены отменённые занятия и ячейки в PDF.

### Надёжная синхронизация с базой (#8)

**Что появилось.** Исправления, чтобы данные не терялись и не дублировались.

**Как это работает.**
- Если публикация нескольких файлов оборвалась на середине, повтор больше
  не записывает уже отправленные файлы второй раз.
- Пока вкладка открыта, данные обновляются раз в минуту: чужие публикации
  и отметки зачётов появляются без перезагрузки страницы.
- Если таблиц расписания в базе ещё нет, редактор видит предупреждение
  сразу при входе и в «Администрирование → Данные».
- При закрытии вкладки с неопубликованными загрузками браузер
  предупреждает, что они пропадут.

### Зачёты: отметить все разом и печать с выбором (#9)

**Что появилось.** Быстрая отметка зачётов и гибкая печать.

**Как это работает.**
- В шапке таблицы недельного плана есть флажок: щелчок отмечает зачётными
  все дисциплины таблицы, повторный щелчок снимает все. Если отмечена
  часть, флажок показывает промежуточное состояние.
- Пункт «Зачёты…» в меню PDF открывает окно, где выбираются группы (одна или
  все), недели (весь семестр, текущая неделя или выбранные) и нужно ли
  начинать каждую группу с новой страницы. Окно сразу показывает, сколько
  зачётов попадёт в PDF.
- Неделя зачёта считается как последняя неделя дисциплины по плану.

### Словари: короткие названия и свойства строк плана (#10)

**Что появилось.** Вкладка «Словари».

**Как это работает.**
- **Короткие названия.** Для дисциплин, преподавателей, групп и аудиторий
  можно задать короткое название. Оно показывается на экране везде: в списке,
  заголовках, плане, карточках расписания, журнале изменений. Полное
  название остаётся во всплывающей подсказке, в поиске, в PDF и в файлах.
- Дисциплина узнаётся без «1-»/«2-» и «(1 подгруппа)», поэтому одно
  короткое название действует во всех группах и подгруппах. Обрезанное
  название из плана связывается с полным из расписания, если совпадение
  однозначное.
- **Свойства строк плана.** В «Словари → Свойства строк» создаются свойства
  с названием, цветом и порядком. В плане у каждой строки есть кнопка
  «+ свойство», а над таблицей отбор строк по свойству со счётчиками.
- Изменять словари могут редактор и администратор, правки других
  пользователей подтягиваются раз в минуту.
- После обновления нужно выполнить `schema.sql` ещё раз.

## 12 ноября 2026

### PDF: выбор недель и отдельные файлы (#11)

**Что появилось.** Печать расписания за несколько недель.

**Как это работает.**
- Пункты меню PDF «Открытое расписание…» и «Все группы…» открывают окно.
  Можно оставить текущую неделю или отметить нужные недели флажками
  (есть кнопки «все» и «снять»).
- При двух и более неделях выбирается вид: одним файлом, где каждая неделя
  начинается с новой страницы, или каждая неделя отдельным файлом.
- Недели без занятий у выбранной группы помечены «(пусто)» и пропускаются.
- В окне «Зачёты…» появился такой же выбор: одним файлом или по файлу
  на неделю.
- Файлы называются понятно, например «Расписание группы X, неделя 13.pdf».
  При сохранении нескольких файлов браузер может один раз спросить
  разрешение.

### Роль «Просмотр» и отметки «просмотрено» (#12)

**Что появилось.** Роль «Просмотр» видит только расписание, а каждый
пользователь отмечает, какие изменения он уже видел.

**Как это работает.**
- **Роль «Просмотр»** видит только вкладку «Расписание» и печатает только
  расписание. Недельный план, журнал изменений, словари, «Открыть файлы…»
  и печать зачётов скрыты. Метки «Зачёт» в карточках расписания остаются.
- **Отметки «просмотрено».** В панели «Изменения этой недели» у каждого
  изменения есть галочка. Отметки личные: у каждого пользователя свои.
- Непросмотренные изменения стоят сверху, просмотренные свёрнуты в группу
  «Просмотренные (N)» внизу. Есть кнопка «отметить все просмотренными».
- Одно изменение отмечается сразу везде: у группы, у преподавателя
  и у аудитории.
- После обновления нужно выполнить `schema.sql` ещё раз.

### Счётчик непросмотренных и перенос зачётов (#13)

**Что появилось.** Видно, сколько изменений вы ещё не посмотрели,
и в журнал попадают переносы зачётов.

**Как это работает.**
- На вкладке «Расписание» красный счётчик показывает, сколько изменений
  текущей недели вы ещё не просмотрели.
- Пометки «изм.», «Новое», «Изменено» и «Отменено» исчезают, когда
  изменение отмечено просмотренным. Метка «Зачёт» остаётся всегда.
- **Перенос зачёта.** Зачёт стоит на последней паре дисциплины в последней
  неделе по плану. Если после публикации плана или расписания он сдвинулся,
  в журнал пишется запись «Перенос зачётов», например «было: нед. 13 →
  стало: нед. 12, Чт 21.11, 2 пара». Запись видна в «Изменениях этой
  недели» у старой и новой недели, в журнале и в счётчике, пока её
  не отметят просмотренной.
- После обновления нужно выполнить `schema.sql` ещё раз.

## 14 ноября 2026

### Сводные таблицы по группам, преподавателям и аудиториям (#14)

**Что появилось.** Расписание всех групп, всех преподавателей или всех
аудиторий в одной таблице, со своим порядком столбцов у каждого
пользователя.

**Как это работает.**
- В списке слева вверху есть пункты «Все группы», «Все преподаватели»
  и «Все аудитории». Столбцы таблицы — группы, преподаватели или аудитории,
  строки — пары по дням недели.
- У групп над шапкой идёт строка курсов. В сводных по преподавателям
  и аудиториям название группы выделено цветом. Щелчок по заголовку
  открывает расписание этого столбца, накладки подсвечены.
- **Настройка столбцов.** Кнопка «Настроить столбцы» показывает над каждым
  заголовком стрелки ← → и глазик (скрыть столбец). Заголовки можно
  перетаскивать мышкой. Есть «показать все» и «вернуть обычный порядок».
- Порядок и скрытые столбцы личные: под таблицей написано, для какого
  пользователя они применяются, у остальных порядок прежний.
- Роль «Просмотр» видит только расписание групп: вкладки «Преподаватели»
  и «Аудитории» скрыты, преподаватели и аудитории в карточках показаны
  обычным текстом.
- После обновления нужно выполнить `schema.sql` ещё раз.

### Пара в первом столбце, изменения и зачёты в сводной (#15, #16)

**Что появилось.** Расписание стало компактнее, а в сводной таблице видны
изменения и зачёты.

**Как это работает.**
- В расписании группы, преподавателя и аудитории номер пары и время стоят
  в отдельном первом столбце, а не повторяются в каждой ячейке.
- В сводной таблице показываются метки «Новое», «Изменено», «Отменено»
  и «Зачёт» по тем же правилам, что в расписании одной группы: после
  отметки «просмотрено» метка исчезает.
- Метки стоят над названием группы, как в карточках расписания (#16).
- Исправлена ширина вкладок «Группы / Преподаватели / Аудитории» в списке
  слева.

### Метки показывают все непросмотренные изменения недели (#17)

**Что появилось.** Раньше метки в сетке показывали только изменения
последней загрузки недели. Теперь видны все изменения недели, которые вы
ещё не отметили просмотренными, по всем загрузкам.

**Как это работает.**
- Изменения сводятся по месту (группа, день, пара, подгруппа). «Было» —
  как стояло до первого непросмотренного изменения, «стало» — текущее
  расписание. Если пару поменяли, а потом вернули как было, метки нет.
- Метка держится, пока у этого места есть непросмотренные изменения.
  Отметка «просмотрено» в панели убирает её.
- Если неделю загрузили заново как новую или удалили, история изменений
  этой недели начинается сначала. Загрузка «без изменений» метки
  больше не прячет.

### Схема Supabase применяется автоматически (#19)

**Что появилось.** Больше не нужно после каждого обновления открывать
Supabase → SQL Editor и выполнять `schema.sql` вручную.

**Как это работает.**
- После push в `main`, где изменился `supabase/schema.sql`, GitHub Actions
  сам выполняет его в базе Supabase (workflow «Apply Supabase schema»).
- Запустить вручную можно на вкладке **Actions → Apply Supabase schema →
  Run workflow**.
- Скрипт выполняется одной транзакцией: если что-то пошло не так, база
  остаётся как была, а в Actions видна ошибка.
- Нужен один раз добавленный секрет репозитория `SUPABASE_DB_URL` — строка
  подключения *Session pooler* из Supabase (Connect → Connection String).
  Пошагово — в README.
