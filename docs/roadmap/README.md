## Как вести отдельное направление

Создаём файл с понятным именем, например `название-направления.md`,
и описываем его по шаблону ниже. Направления можно развивать параллельно;
общие данные и зависимости между ними указываем явно.

### Шаблон описания

- **Название и статус:** идея / обсуждение / запланировано / в работе / готово / отложено.
- **Пользователи:** кому нужен модуль или мини-продукт.
- **Задача и польза:** что человек сможет сделать.
- **Минимальная версия:** какие возможности нужны в первую очередь.
- **Дальнейшие идеи:** что можно добавить позже.
- **Связи с EduLOG:** общие данные, роли, интерфейсы и зависимости.
- **Ближайшие шаги:** небольшой список конкретных задач.
- **Открытые вопросы:** что ещё нужно решить.
- **Реализация:** ссылки на задачи, ветки и pull request, когда они появятся.

Ветки Git создаём под конкретные изменения, когда приступаем к реализации,
и связываем с документом направления. Планирование направления само по себе
не требует отдельной ветки.
