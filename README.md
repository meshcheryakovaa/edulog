# EduLOG — План и расписание

Рабочий стол диспетчера учебной части: недельный план нагрузки по группам,
преподавателям и аудиториям и сетка расписания. Приложение работает целиком
в браузере и распространяется как **один HTML-файл** без сервера.

[Идеи, направления и планы развития](docs/roadmap/README.md) — отдельное место

## Многопользовательский режим

Если подключить бесплатный проект [Supabase](https://supabase.com), сайт
работает с входом по email и паролем, а план, расписание и отметки зачётов
становятся общими для всех пользователей. Без настройки приложение работает
локально, как раньше.

**Роли**

| Роль | Что может |
|---|---|
| Ожидает | зарегистрировался; данных не видит, пока администратор не одобрит |
| Просмотр | видит только расписание (с отметками зачётов) и печатает его в PDF; отмечает у изменений недели, что просмотрел |
| Редактор | публикует новые файлы плана и расписания, отмечает зачёты |
| Администратор | всё перечисленное, плюс раздел «Администрирование»: заявки, роли, опубликованные файлы, журнал действий |
| Заблокирован | доступ закрыт |

Первый зарегистрированный пользователь автоматически становится
администратором. Права проверяются на сервере (Row Level Security), поэтому
публичный ключ в коде страницы ничего лишнего не открывает.

**Настройка (один раз)**

1. Создайте проект на supabase.com.
2. В **SQL Editor** выполните целиком файл [`supabase/schema.sql`](supabase/schema.sql).
3. В **Authentication → URL Configuration** укажите *Site URL*:
   `https://meshcheryakovaa.github.io/edulog/` (туда ведут ссылки из писем
   подтверждения и сброса пароля).
4. В **Project Settings → API** скопируйте *Project URL* и ключ *anon public*.
5. В репозитории GitHub: **Settings → Secrets and variables → Actions →
   Variables** добавьте переменные `SUPABASE_URL` и `SUPABASE_ANON_KEY`
   (или впишите значения в `src/config.js`).
6. Перезапустите workflow (или сделайте push в `main`) и сразу
   зарегистрируйтесь на сайте первым — вы станете администратором.

Как публиковать данные: редактор или администратор нажимает «Открыть файлы…»,
проверяет, что всё разобралось, и нажимает «Опубликовать». Остальные увидят
новую версию при следующем открытии вкладки. Кнопка «Вернуть опубликованное»
отменяет открытые локально файлы.

Чтобы письма подтверждения не требовались (например, для внутренних
пользователей), отключите **Authentication → Providers → Email → Confirm email**.
Чтобы закрыть самостоятельную регистрацию, отключите **Allow new users to sign up**
и добавляйте пользователей через **Authentication → Users → Invite**.

## Расписание по неделям

Файл расписания (.json, раздел `timetable`) содержит одну или несколько
**целых недель** — отдельные дни не загружаются. Каждый новый файл обновляет
базу только по своим неделям: неделя из файла целиком заменяет такую же в базе
(сопоставление по дате понедельника, а если дат нет — по номеру недели),
остальные недели остаются как были. Ошибочно загруженную неделю можно удалить.

Что поменялось, видно в трёх местах:

- вкладка **«Изменения»** — журнал загрузок: какие недели появились, обновились
  или удалены, и по каждой обновлённой неделе — добавленные, отменённые и
  изменённые занятия (было → стало). Можно оставить только выбранную группу,
  преподавателя или аудиторию;
- **«Расписание»** группы, преподавателя или аудитории — карточки «Новое»,
  «Изменено», отменённые занятия пунктиром и список изменений этой недели;
- **«Недельный план»** — недели с изменениями отмечены точкой в шапке таблицы,
  внизу — список изменений расписания для выбранного.

В списке слева пометка «изм.» означает, что выбранного коснулась последняя загрузка.

В многопользовательском режиме недели хранятся в таблице `sched_weeks`, журнал —
в `sched_uploads`. **После обновления приложения выполните `supabase/schema.sql`
ещё раз** (скрипт безопасно запускать повторно). Расписание, опубликованное раньше
одним файлом, при первой публикации переносится в новую базу. В локальном режиме
(без Supabase) база недель и журнал хранятся в этом браузере.

## Словари

Вкладка **«Словари»**:

- **Дисциплины, Преподаватели, Группы, Аудитории** — истинное название (как в файлах)
  и короткое название, которое показывается на экране: в списке слева, в таблицах
  плана, в карточках расписания и в изменениях. Истинное название остаётся во
  всплывающей подсказке, в поиске, в PDF и в файлах. Пустое поле — показывается
  истинное. Дисциплина узнаётся по названию без «1-»/«2-» и «(1 подгруппа)»;
  обрезанное название из плана связывается с полным из расписания;
- **Свойства строк** — список свойств (название, короткое название, цвет, порядок),
  которые ставятся строкам (дисциплинам) недельного плана: кнопка «+ свойство»
  рядом с названием строки. Над таблицей плана по свойству можно отобрать строки.
  Удаление свойства снимает его со всех строк.

Менять словари может редактор или администратор. В многопользовательском режиме
словари хранятся в таблицах `dict_names`, `props` и `row_props`, изменения пишутся
в журнал действий — **выполните `supabase/schema.sql` ещё раз**. В локальном режиме
словари хранятся в этом браузере.

## Сводная таблица

В разделе «Расписание» вверху списка слева — «Все группы», «Все преподаватели»,
«Все аудитории». Это сводная таблица недели: столбцы — группы, преподаватели или
аудитории, строки — пары, сгруппированные по дням недели. Клик по заголовку столбца
открывает его расписание, накладки подсвечены красным.

Кнопка «Настроить столбцы»: стрелки над названием двигают столбец, глазик скрывает
или показывает его, заголовок можно перетащить мышкой. Порядок и скрытые столбцы
свои у каждого пользователя, у остальных порядок прежний. В многопользовательском
режиме они хранятся в таблице `user_prefs` — **выполните `supabase/schema.sql`
ещё раз**; в локальном режиме — в этом браузере.

Роль «Просмотр» видит только расписание групп: вкладок «Преподаватели» и
«Аудитории» у неё нет.

## Структура

```
src/
  index.html                 разметка страницы
  styles.css                 стили
  config.js                  адрес и ключ Supabase (пусто — локальный режим)
  app.js                     логика приложения
  cloud.js                   вход, общие данные, раздел администратора
  data/
    sample-plan.txt          встроенный пример плана (выгрузка .txt)
    sample-schedule.json     встроенный пример расписания (.json)
supabase/
  schema.sql                 таблицы и права доступа для Supabase
scripts/
  build.mjs                  сборка в один файл (без зависимостей)
.github/workflows/
  release.yml                CI: сборка, GitHub Pages и релизы
```

## Сборка

Нужен Node.js 18+, больше ничего устанавливать не надо.

```sh
npm run build        # или: node scripts/build.mjs
```

Результат: `dist/edulog.html`. Скрипт подставляет внутрь страницы стили,
`app.js` и примеры данных (JSON сжимается). Шрифты Google Fonts остаются
внешней ссылкой; без интернета используются системные шрифты.

Для разработки можно открыть `src/` через любой статический сервер
(`npm run dev`); встроенные примеры в этом режиме не подгружаются,
файлы плана и расписания открываются кнопкой «Открыть файлы…».

## Релиз

```sh
git tag v1.0.0
git push origin v1.0.0
```

Workflow `Build & Release` соберёт `edulog.html` и создаст GitHub Release
с этим файлом. На каждый push в `main` и на pull request файл тоже собирается
и доступен в артефактах запуска, а push в `main` публикует его на GitHub Pages.

Для работы Pages один раз включите в настройках репозитория
**Settings → Pages → Build and deployment → Source: GitHub Actions**.
